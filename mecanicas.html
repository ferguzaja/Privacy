Mecánicas (grants)

5. Mecánicas (grants): el catálogo type

Cada grant se identifica con "type". Todos aceptan además dos campos opcionales:

  • minLevel (int?): nivel mínimo de clase para que aplique.
  • subclassId (string?): el grant solo aplica si el personaje tiene esa subclase.

⚠️ Si adaptas contenido desde 5e.tools u otra fuente externa

El formato de esta app no es el de 5e.tools. Copiar sus datos tal cual produce dos tipos de problema, y conviene distinguirlos:

Errores que rompen el import (el pack entero se rechaza):

Qué pasaEjemplo incorrectoCorrecto
Falta un campo obligatorio del grant. Error: Field 'base' is required for type with serial name 'AC_FORMULA'.{ "type": "AC_FORMULA", "formula": "10 + DEX + CON" }{ "type": "AC_FORMULA", "base": 10, "abilities": ["DEX","CON"] }
Decimal donde se espera un entero.{ "type": "SPEED_BONUS", "bonus": 3.0 }{ "type": "SPEED_BONUS", "bonus": 3 }
Nombre de campo de otro grant. Aquí count es de WEAPON_MASTERY, no de EXTRA_ATTACK.{ "type": "EXTRA_ATTACK", "count": 1 }{ "type": "EXTRA_ATTACK", "totalAttacks": 2 }
Nombre de campo equivocado en un grant con campo obligatorio. Aquí amount es de SPEED_PENALTY/AC_BONUS, no de SPEED_BONUS.{ "type": "SPEED_BONUS", "amount": 3 }{ "type": "SPEED_BONUS", "bonus": 3 }

Datos que se pierden en silencio (el import "funciona", pero falta contenido): la app ignora las claves que no conoce (ignoreUnknownKeys), así que un nombre de campo o de lista equivocado no da error, simplemente no hace nada:

  • Claves opcionales mal escritas, p. ej. "damageType" en vez de "damageTypes" en un DAMAGE_RESISTANCE (todos sus campos son opcionales) → la resistencia queda vacía.
  • "race": [...] en la raíz del pack (la lista se llama species) → las especies no entran.
  • "formula": "…" en cualquier grant → se descarta; usa los campos estructurados.

Antes de importar, comprueba:

  1. Cada grant que uses tiene todos sus campos obligatorios (§5.1–§5.4, en negrita).
  2. Los campos numéricos son enteros salvo los que la guía marca como metros con decimales (SpeciesDef.speed, SENSES, etc.; ver §18).
  3. Las listas del pack usan los nombres exactos: classes, species, backgrounds, feats, spells, invocations, equipment, beasts.
  4. El type de cada grant está escrito exactamente como en el catálogo (un typo degrada a UNKNOWN y la mecánica se pierde sin aviso).

5.1 Recursos y acciones

RESOURCE — recurso rastreable con botones +/−.

{
  "type": "RESOURCE",
  "id": "rage_uses",
  "label": "Furias",
  "icon": "🔥",
  "recovery": "SHORT_REST",
  "scaling": { "rule": "FROM_TABLE", "tableKey": "rage_uses" },
  "hidden": false
}
  • recovery: NONE | SHORT_REST (recupera todos los usos) | SHORT_REST_ONE (corto = +1 uso, largo = todos; p. ej. Canalizar divinidad, Tomar aliento, Forma salvaje) | LONG_REST | DAWN…
  • scaling.rule: FIXED (usa value) | LEVEL | PROFICIENCY | ABILITY_MOD (usa ability) | FROM_TABLE (usa tableKey).
  • Modificadores opcionales de scaling, aplicados en este orden: (regla × multiplier) + bonus, y al final el piso minimum:
    • multiplier (int): multiplica el resultado de la regla (p. ej. 5 → Imposición de manos 5 × nivel).
    • bonus (int): constante que se suma tras el multiplicador (p. ej. 1 → reserva 1 + nivel de Luz sanadora del Brujo Celestial).
    • minimum (int): piso del resultado final. Modela el "mínimo una vez" del SRD en recursos que escalan con un modificador (p. ej. { "rule": "ABILITY_MOD", "ability": "WIS", "minimum": 1 }): si el modificador es ≤ 0, el recurso conserva al menos ese número de usos.
  • Si dos RESOURCE comparten id, el motor conserva el de mayor max. Permite escalar un pool por nivel declarando dos grants con minLevel distintos.
  • hidden: si es true, el pool existe pero no se dibuja como tracker propio (lo consume una acción).

COMBAT_TOGGLE — estado on/off; puede anidar más grants en onActivate.

{
  "type": "COMBAT_TOGGLE",
  "id": "rage_active",
  "label": "Activar Furia",
  "costResource": "rage_uses",
  "costAmount": 1,
  "onActivate": [
    { "type": "DAMAGE_RESISTANCE", "damageTypes": ["bludgeoning","piercing","slashing"], "condition": "WHILE_RAGING" }
  ]
}

COMBAT_ACTION — acción puntual que gasta un recurso; puede tirar dados.

{
  "type": "COMBAT_ACTION",
  "id": "brutal_strike_action",
  "label": "Golpe brutal",
  "costResource": "rage_uses",
  "costAmount": 1,
  "rollDice": "1d10",
  "rollKind": "DAMAGE",
  "description": "…"
}

CHOICE — abre un selector para el jugador.

{
  "type": "CHOICE",
  "id": "asi_4",
  "title": "Mejora de característica",
  "pick": 1,
  "kind": "FEAT",
  "level": 4
}

kind común: SKILL, EXPERTISE, SKILL_OR_EXPERTISE, FEAT, SUBCLASS, SPELL, WEAPON_MASTERY, ABILITY_SCORE_IMPROVEMENT, CUSTOM.

Notas de los kind de habilidad:

  • SKILL: otorga COMPETENCIA. Las habilidades que el personaje ya tiene se muestran deshabilitadas ("ya la tienes") y no son seleccionables.
  • EXPERTISE: otorga PERICIA; solo ofrece habilidades en las que YA se es competente.
  • SKILL_OR_EXPERTISE: patrón de dotes tipo Mente aguda / Observador. Si el personaje NO es competente en la habilidad elegida, gana competencia; si YA lo es, gana pericia. No deshabilita las conocidas (elegir una conocida es lo que da la pericia).

Campos extra según kind: pool, count, category, featId, spellLevel, fromClass, fromClasses, points, options, schools, ritual, pickFromStat, grantsSavingThrowProficiency.

Campos que afinan una elección de conjuro (kind: "SPELL") y de característica (kind: "ABILITY_SCORE_IMPROVEMENT"), usados por las dotes del PHB 2024:

  • schools (lista de string, default []): restringe el selector a esas escuelas de magia; vacío = cualquiera. Patrón de Influencia feérica (["ADIVINACION","ENCANTAMIENTO"]) e Influencia sombría (["ILUSION","NIGROMANCIA"]).
  • ritual (bool, default false): solo ofrece conjuros que puedan lanzarse como ritual. Lo usa Lanzador ritual.
  • pickFromStat (string?, default null): si está presente, el número de elecciones (pick) se calcula en runtime en vez de usar el pick fijo. Valor soportado: "PROFICIENCY_BONUS" → pick = bonificador de competencia del personaje (escala al subir de nivel). Lo usa Lanzador ritual (eliges tantos conjuros ritual como tu bonif. de competencia).
  • grantsSavingThrowProficiency (bool, default false): solo con kind: "ABILITY_SCORE_IMPROVEMENT". Además de subir la característica elegida, otorga COMPETENCIA en su tirada de salvación (emite SAVE_PROF_<código>). Patrón de la dote Resiliente; las salvaciones en las que ya seas competente aparecen deshabilitadas.
{
  "type": "CHOICE",
  "id": "fey_touched_spell",
  "title": "Influencia feérica: conjuro a elección",
  "pick": 1,
  "kind": "SPELL",
  "spellLevel": 1,
  "schools": ["ADIVINACION", "ENCANTAMIENTO"]
}
{
  "type": "CHOICE",
  "id": "ritual_caster_spells",
  "title": "Lanzador ritual: conjuros ritual",
  "kind": "SPELL",
  "spellLevel": 1,
  "ritual": true,
  "pickFromStat": "PROFICIENCY_BONUS"
}

CHOICE kind=SPELL dentro de un rasgo de clase/subclase: los conjuros elegidos así (p. ej. Arcanum místico del Brujo, Conjuros característicos o Maestría del Mago) se agrupan en la ficha, pestaña Magia, en la sección propia "rasgo de clase" (SpellSource.CLASS_FEATURE), separados de los aprendidos por la progresión normal ("clase"). Es automático, sin campos extra. Lo mismo aplica a los INNATE_SPELL declarados en rasgos de subclase (p. ej. "Conjuros del infernal"). Si spellLevel supera el nivel máximo de espacios del personaje (Arcanum), el catálogo de conjuros muestra ese nivel y la elección reemplaza el conjuro del slot de ese rasgo.

{
  "type": "CHOICE",
  "id": "resilient_boost",
  "title": "Mejora de Resiliente",
  "kind": "ABILITY_SCORE_IMPROVEMENT",
  "pool": ["STR", "DEX", "CON", "INT", "WIS", "CHA"],
  "points": 1,
  "grantsSavingThrowProficiency": true
}

Para kind: "CUSTOM" defines tú las opciones, y cada una puede otorgar grants al elegirse:

{
  "type": "CHOICE",
  "id": "divine_fury_type",
  "title": "Tipo de daño",
  "pick": 1,
  "kind": "CUSTOM",
  "options": [
    { "id": "opt_necrotic", "display": { "name": "Necrótico" }, "grants": [] },
    { "id": "opt_radiant",  "display": { "name": "Radiante"  }, "grants": [] }
  ]
}

5.2 Combate y defensa

Campos obligatorios en negrita. El resto son opcionales (tienen valor por defecto y puedes omitirlos). Omitir un campo obligatorio rompe el import con un error tipo Field 'xxx' is required for type with serial name 'YYY'. Los números marcados como int son enteros: un decimal (3.0) también rompe el parseo; usa 3.

⚠️ SPEED_BONUS usa bonus; SPEED_PENALTY usa amount. No son intercambiables. Poner "amount" en un SPEED_BONUS rompe el import (Field 'bonus' is required…), porque bonus es obligatorio y amount se descarta por desconocido.

Ejemplos listos para copiar:

{ "type": "AC_FORMULA", "base": 10, "abilities": ["DEX", "CON"] }
{ "type": "AC_BONUS", "amount": 1, "condition": "WHILE_ATTUNED" }
{ "type": "SPEED_BONUS", "bonus": 3 }
{ "type": "DAMAGE_RESISTANCE", "damageTypes": ["BLUDGEONING", "PIERCING", "SLASHING"] }
{ "type": "EXTRA_ATTACK", "totalAttacks": 2 }
La AC_FORMULA modela "10 + modificadores" como datos estructurados: base es el 10 y abilities son los modificadores que se suman (["DEX","CON"] = + mod. DES + mod. CON). No existe un campo formula de texto: una cadena como "10 + DEX + CON" no se interpreta.

Defensas de daño y de estados. Los tipos de damageTypes se comparan sin importar si van en inglés ("fire") o en español ("Fuego", con o sin tilde); los 13 tipos del juego son acid, bludgeoning, cold, fire, force, lightning, necrotic, piercing, poison, psychic, radiant, slashing y thunder. Si coinciden resistencia y vulnerabilidad sobre un tipo, el daño se divide entre 2 y luego se duplica (redondeando a la baja); la inmunidad gana a ambas. condition limita cuándo aplica (p. ej. WHILE_RAGING). En la ficha, el diálogo de daño recibido pide el tipo y aplica estas defensas. CONDITION_IMMUNITY.conditions usa los nombres de estado de la app (ASUSTADO, HECHIZADO, ENVENENADO, CEGADO, ENSORDECIDO, PARALIZADO, EXHAUSTO…; no distingue mayúsculas). Al cobrar efecto, la ficha quita el estado si ya lo tenías y no deja aplicarlo. Valores de condition útiles aquí: WHILE_RAGING, WHILE_NOT_INCAPACITATED.

{ "type": "CONDITION_IMMUNITY", "conditions": ["ASUSTADO", "HECHIZADO"], "condition": "WHILE_NOT_INCAPACITATED" }

attackTypes (en DAMAGE_BONUS y ATTACK_BONUS) filtra a qué ataques aplica el bono. Vacío = todos. El motor clasifica cada arma y le asigna estas etiquetas:

EtiquetaAplica a
ALLcualquier ataque (siempre presente)
melee_str / melee_dexcuerpo a cuerpo según use FUE o DES
ranged_str / ranged_dexa distancia según use FUE o DES
melee_one_handed / melee_two_handedcuerpo a cuerpo según manos requeridas
melee_heavycuerpo a cuerpo con la propiedad «pesada» (Maestro en armas pesadas)
thrownarma con la propiedad arrojadiza
lightarma con la propiedad ligera
melee_one_handed_offhand_freecuerpo a cuerpo a una mano con la otra mano libre (estilo Duelo)

Ejemplo — Maestro en armas pesadas (daño extra = bonif. de competencia al golpear con arma pesada):

{ "type": "DAMAGE_BONUS", "source": "PROFICIENCY", "attackTypes": ["melee_heavy"] }

COMPUTED_STAT es el comodín para pasivas numéricas simples que no justifican un type propio. Ejemplo — Maestro en armaduras medias, que sube a 3 el tope de modificador de DES de la armadura media:

SPELL_DAMAGE_BONUS — los filtros se combinan con Y; un filtro vacío no restringe. schools usa los códigos de escuela del catálogo (ABJURACION, ADIVINACION, CONJURACION, ENCANTAMIENTO, EVOCACION, ILUSION, NIGROMANCIA, TRANSMUTACION); damageTypes, los tipos de daño del conjuro; spellListClassIds, ids de clase ("wizard"). spellsFromChoice es el id de un CHOICE cuyas selecciones son conjuros (Descarga agónica elige un truco; mientras no se elija, no aplica a ninguno). perRoll: true suma el bono a CADA tirada de daño (cada rayo); false, a una sola tirada del lanzamiento. Ejemplos:

{ "type": "SPELL_DAMAGE_BONUS", "ability": "INT", "schools": ["EVOCACION"], "spellListClassIds": ["wizard"], "label": "Evocación potenciada" }
{ "type": "SPELL_DAMAGE_BONUS", "ability": "CHA", "spellsFromChoice": "agonizing_blast_cantrip", "perRoll": true, "label": "Descarga agónica" }

WEAPON_ABILITY — mientras esté activo, el modificador de ability sustituye al de Fuerza o Destreza en el ataque y el daño del arma de las armas que cumplan los filtros. weaponIds vacío = cualquier arma. meleeOnly limita a cuerpo a cuerpo. grantsProficiency: true hace que cuentes como competente con el arma (Pacto de la hoja). condition: "TOGGLE:<id>" lo activa solo mientras ese interruptor de la ficha esté encendido (Pacto de la hoja usa TOGGLE:pact_weapon_bound).

{ "type": "WEAPON_ABILITY", "ability": "CHA", "meleeOnly": true, "grantsProficiency": true, "condition": "TOGGLE:pact_weapon_bound" }

Elecciones de conjuro con usos gratis (usesPerRest). Un CHOICE kind=SPELL puede llevar usesPerRest (entero): el conjuro elegido se lanza ese número de veces entre descansos largos SIN gastar espacio. La ficha le pone su propio contador y un botón «Usar»; se recupera con descanso largo (el corto no). Sin el campo, el conjuro elegido usa espacios como cualquier otro. Es el patrón del Arcanum místico del Brujo:

{ "type": "CHOICE", "id": "mystic_arcanum_6_spell", "title": "Arcanum místico: conjuro de nivel 6",
  "kind": "SPELL", "spellLevel": 6, "fromClass": "warlock", "usesPerRest": 1, "reopenable": true }

5.4 Situacionales / objetos (declarativos)

Se conservan tipados y se muestran como texto; la mayoría no produce cálculo automático: ADVANTAGE, AUTO_SUCCESS, LIGHT_SOURCE, FUEL, MAGNIFICATION, LOCK, LIFT_CAPACITY_MULTIPLIER, MATERIAL_COMPONENT_SUBSTITUTE, EXPAND_BUNDLE, UTILITY_ACTION.

UNKNOWN no se escribe a mano: es el resultado de un type que el motor no reconoce.

18. Unidades de distancia (importante)

Todas las distancias de la app están en METROS. No hay mezcla de unidades: velocidad, sentidos, alcances de arma, radios de luz y velocidades de bestia usan metros. Equivalencia del juego: 5 pies = 1,5 m (1 casilla).

Campos que son distancias (todos en metros):

  • SpeciesDef.speed y SpeciesDef.darkvision → metros (double). En srd_base.json: elfo speed: 9.0, enano darkvision: 36.0, goliat speed: 10.5 y darkvision: 0.0.
  • Grant SENSES → darkvision, blindsight, tremorsense, truesight (metros, double).
  • SpeedBonusGrant.bonus / SpeedPenaltyGrant.amount → metros.
  • WeaponRange { normal, long, unit }, LightSourceGrant, Measure { amount, unit } → el unit sigue existiendo y por defecto es "m".
  • BeastDef.speed/swim/fly/climb → metros.

Como todo comparte unidad, el motor compara y acumula sin convertir (p. ej. SheetData.darkvision toma el máximo entre el darkvision de la especie y los grants SENSES). La UI solo añade el sufijo " m" al mostrar (con coma decimal: 10,5 m).

Regla práctica:

DatoUnidadEjemplo
SpeciesDef.speed, SpeciesDef.darkvisionmetros"speed": 9 = 9 m
SENSES (darkvision/blindsight/…)metros"darkvision": 18 = 18 m
SpeedBonusGrant.bonus, SpeedPenaltyGrant.amountmetros"bonus": 3 = +3 m
WeaponRange, LightSourceGrant, Measuresegún unit (default m){ "normal": 24, "unit": "m" }
BeastDef.speed/swim/fly/climbmetros"speed": 12 = 12 m

Compatibilidad con packs antiguos (en pies)

Los packs exportados antes de esta unificación guardaban velocidad y sentidos de especie en pies ("speed": 30, "darkvision": 60, SENSES con darkvisionFeet/blindsightFeet/…). Esos packs se importan igual: al cargarlos, la app detecta que no declaran metros y convierte esos valores a metros automáticamente (m = pies × 0,3), renombrando las claves *Feet.

El marcador es la clave distanceUnit en la raíz del pack:

  • "distanceUnit": "m" → el pack ya está en metros; se usa tal cual.
  • sin distanceUnit → se asume que especie y sentidos están en pies y se convierten al cargar.

Los packs que genera la app y el SRD base declaran "distanceUnit": "m". Si creas un pack nuevo a mano, escribe las distancias en metros y añade "distanceUnit": "m" para evitar cualquier conversión. (Las bestias nunca se convierten: su speed ya estaba en metros.)
