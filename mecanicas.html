Mecánicas (grants)

5. Mecánicas (grants): el catálogo type

Cada grant se identifica con "type". Todos aceptan además dos campos opcionales:

  • minLevel (int?): nivel mínimo de clase para que aplique.
  • subclassId (string?): el grant solo aplica si el personaje tiene esa subclase.

5.1 Recursos y acciones

RESOURCE — recurso rastreable con botones +/−.

{
  "type": "RESOURCE",
  "id": "rage_uses",
  "label": "Furias",
  "icon": "🔥",
  "recovery": "SHORT_REST",
  "scaling": { "rule": "FROM_TABLE", "tableKey": "rage_uses" },
  "hidden": false
}
  • recovery: NONE | SHORT_REST | LONG_REST | DAWN…
  • scaling.rule: FIXED (usa value) | LEVEL | PROFICIENCY | ABILITY_MOD (usa ability) | FROM_TABLE (usa tableKey). multiplier opcional multiplica el resultado.
  • hidden: si es true, el pool existe pero no se dibuja como tracker propio (lo consume una acción).

COMBAT_TOGGLE — estado on/off; puede anidar más grants en onActivate.

{
  "type": "COMBAT_TOGGLE",
  "id": "rage_active",
  "label": "Activar Furia",
  "costResource": "rage_uses",
  "costAmount": 1,
  "onActivate": [
    { "type": "DAMAGE_RESISTANCE", "damageTypes": ["bludgeoning","piercing","slashing"], "condition": "WHILE_RAGING" }
  ]
}

COMBAT_ACTION — acción puntual que gasta un recurso; puede tirar dados.

{
  "type": "COMBAT_ACTION",
  "id": "brutal_strike_action",
  "label": "Golpe brutal",
  "costResource": "rage_uses",
  "costAmount": 1,
  "rollDice": "1d10",
  "rollKind": "DAMAGE",
  "description": "…"
}

CHOICE — abre un selector para el jugador.

{
  "type": "CHOICE",
  "id": "asi_4",
  "title": "Mejora de característica",
  "pick": 1,
  "kind": "FEAT",
  "level": 4
}

kind común: SKILL, EXPERTISE, SKILL_OR_EXPERTISE, FEAT, SUBCLASS, SPELL, WEAPON_MASTERY, ABILITY_SCORE_IMPROVEMENT, CUSTOM.

Notas de los kind de habilidad:

  • SKILL: otorga COMPETENCIA. Las habilidades que el personaje ya tiene se muestran deshabilitadas ("ya la tienes") y no son seleccionables.
  • EXPERTISE: otorga PERICIA; solo ofrece habilidades en las que YA se es competente.
  • SKILL_OR_EXPERTISE: patrón de dotes tipo Mente aguda / Observador. Si el personaje NO es competente en la habilidad elegida, gana competencia; si YA lo es, gana pericia. No deshabilita las conocidas (elegir una conocida es lo que da la pericia).

Campos extra según kind: pool, count, category, featId, spellLevel, fromClass, fromClasses, points, options, schools, ritual, pickFromStat, grantsSavingThrowProficiency.

Campos que afinan una elección de conjuro (kind: "SPELL") y de característica (kind: "ABILITY_SCORE_IMPROVEMENT"), usados por las dotes del PHB 2024:

  • schools (lista de string, default []): restringe el selector a esas escuelas de magia; vacío = cualquiera. Patrón de Influencia feérica (["ADIVINACION","ENCANTAMIENTO"]) e Influencia sombría (["ILUSION","NIGROMANCIA"]).
  • ritual (bool, default false): solo ofrece conjuros que puedan lanzarse como ritual. Lo usa Lanzador ritual.
  • pickFromStat (string?, default null): si está presente, el número de elecciones (pick) se calcula en runtime en vez de usar el pick fijo. Valor soportado: "PROFICIENCY_BONUS" → pick = bonificador de competencia del personaje (escala al subir de nivel). Lo usa Lanzador ritual (eliges tantos conjuros ritual como tu bonif. de competencia).
  • grantsSavingThrowProficiency (bool, default false): solo con kind: "ABILITY_SCORE_IMPROVEMENT". Además de subir la característica elegida, otorga COMPETENCIA en su tirada de salvación (emite SAVE_PROF_<código>). Patrón de la dote Resiliente; las salvaciones en las que ya seas competente aparecen deshabilitadas.
{
  "type": "CHOICE",
  "id": "fey_touched_spell",
  "title": "Influencia feérica: conjuro a elección",
  "pick": 1,
  "kind": "SPELL",
  "spellLevel": 1,
  "schools": ["ADIVINACION", "ENCANTAMIENTO"]
}
{
  "type": "CHOICE",
  "id": "ritual_caster_spells",
  "title": "Lanzador ritual: conjuros ritual",
  "kind": "SPELL",
  "spellLevel": 1,
  "ritual": true,
  "pickFromStat": "PROFICIENCY_BONUS"
}
{
  "type": "CHOICE",
  "id": "resilient_boost",
  "title": "Mejora de Resiliente",
  "kind": "ABILITY_SCORE_IMPROVEMENT",
  "pool": ["STR", "DEX", "CON", "INT", "WIS", "CHA"],
  "points": 1,
  "grantsSavingThrowProficiency": true
}

Para kind: "CUSTOM" defines tú las opciones, y cada una puede otorgar grants al elegirse:

{
  "type": "CHOICE",
  "id": "divine_fury_type",
  "title": "Tipo de daño",
  "pick": 1,
  "kind": "CUSTOM",
  "options": [
    { "id": "opt_necrotic", "display": { "name": "Necrótico" }, "grants": [] },
    { "id": "opt_radiant",  "display": { "name": "Radiante"  }, "grants": [] }
  ]
}

COMPUTED_STAT es el comodín para pasivas numéricas simples que no justifican un type propio. El motor emite ComputedStat(key, value) y lo propaga a stats; mode: "SUM" acumula con otros de la misma key, mode: "MAX" conserva el mayor. Ejemplo — Maestro en armaduras medias, que sube a 3 el tope de modificador de DES de la armadura media:

{ "type": "COMPUTED_STAT", "key": "MEDIUM_ARMOR_MAX_DEX", "value": 3, "mode": "MAX" }

5.4 Situacionales / objetos (declarativos)

Se conservan tipados y se muestran como texto; la mayoría no produce cálculo automático: ADVANTAGE, AUTO_SUCCESS, LIGHT_SOURCE, FUEL, MAGNIFICATION, LOCK, LIFT_CAPACITY_MULTIPLIER, MATERIAL_COMPONENT_SUBSTITUTE, EXPAND_BUNDLE, UTILITY_ACTION.

UNKNOWN no se escribe a mano: es el resultado de un type que el motor no reconoce.

18. Unidades de distancia (importante)

Todas las distancias de la app están en METROS. No hay mezcla de unidades: velocidad, sentidos, alcances de arma, radios de luz y velocidades de bestia usan metros. Equivalencia del juego: 5 pies = 1,5 m (1 casilla).

Campos que son distancias (todos en metros):

  • SpeciesDef.speed y SpeciesDef.darkvision → metros (double). En srd_base.json: elfo speed: 9.0, enano darkvision: 36.0, goliat speed: 10.5 y darkvision: 0.0.
  • Grant SENSES → darkvision, blindsight, tremorsense, truesight (metros, double).
  • SpeedBonusGrant.bonus / SpeedPenaltyGrant.amount → metros.
  • WeaponRange { normal, long, unit }, LightSourceGrant, Measure { amount, unit } → el unit sigue existiendo y por defecto es "m".
  • BeastDef.speed/swim/fly/climb → metros.

Como todo comparte unidad, el motor compara y acumula sin convertir (p. ej. SheetData.darkvision toma el máximo entre el darkvision de la especie y los grants SENSES). La UI solo añade el sufijo " m" al mostrar (con coma decimal: 10,5 m).

Regla práctica:

DatoUnidadEjemplo
SpeciesDef.speed, SpeciesDef.darkvisionmetros"speed": 9 = 9 m
SENSES (darkvision/blindsight/…)metros"darkvision": 18 = 18 m
SpeedBonusGrant.bonus, SpeedPenaltyGrant.amountmetros"bonus": 3 = +3 m
WeaponRange, LightSourceGrant, Measuresegún unit (default m){ "normal": 24, "unit": "m" }
BeastDef.speed/swim/fly/climbmetros"speed": 12 = 12 m

Compatibilidad con packs antiguos (en pies)

Los packs exportados antes de esta unificación guardaban velocidad y sentidos de especie en pies ("speed": 30, "darkvision": 60, SENSES con darkvisionFeet/blindsightFeet/…). Esos packs se importan igual: al cargarlos, la app detecta que no declaran metros y convierte esos valores a metros automáticamente (m = pies × 0,3), renombrando las claves *Feet.

El marcador es la clave distanceUnit en la raíz del pack:

  • "distanceUnit": "m" → el pack ya está en metros; se usa tal cual.
  • sin distanceUnit → se asume que especie y sentidos están en pies y se convierten al cargar.

Los packs que genera la app y el SRD base declaran "distanceUnit": "m". Si creas un pack nuevo a mano, escribe las distancias en metros y añade "distanceUnit": "m" para evitar cualquier conversión. (Las bestias nunca se convierten: su speed ya estaba en metros.)
